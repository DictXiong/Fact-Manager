# 使用指南

## 网页流程

1. 登录，创建事实库，填写主题说明。每个库可以在设置页自定义完整提取 Prompt。
2. 添加来源：直接录入文字、上传 UTF-8 TXT / Markdown，或绑定 RAGFlow Dataset。
   PDF、Word、扫描件等先在 `https://rag.example.com` 上传解析，再同步到事实库。
   Dataset 必须是配置的 RAGFlow API Key 可以访问的数据集。
3. 在 **来源与提取** 页面点击 **同步来源**，保存已完成解析的文档原件和全部分块。
   文档在 RAGFlow 更新或重新解析后，再点击此按钮更新事实库的证据快照。同步由网页后台任务执行，
   页面展示进度和结果；不会自动定时同步，也不调用事实提取模型。
   任务遇到库忙会提示重试。停用来源或取消 Dataset 绑定会使该来源的事实停止提供。
4. 明确点击 **提取候选事实** 才调用配置的模型，可能产生 API 费用。
   查看任务进度；已完成的分块可增量跳过，失败任务可重新启动。
   模型只能根据原文提出候选事实，引用必须是对应证据的逐字原文。
   提取时补充文档上下文与相邻分块；Word 上下文保留段落顺序，用于识别项目和团队角色。
   上下文不能代替目标分块的引用；引用失败时最多请求模型纠正一次，仍失败则停止该分块。
   同一提示版本已生成的事实会随增量进度提供给模型，减少中英文翻译与重复摘要产生的重复项。
   PPTX 提取补充当前页原始文本框的坐标和分组，用于多栏人员、指标和年度规划的对应；按演示文稿实际页序定位，支持重新排列过的幻灯片。
   模型可返回原文行号区间，由程序复原连续原文引用，避免模型删除项目符号或自行拼接；引用仍只能来自归档分块。
   演示文稿补充提示保留公司/产品/测试的不同范围，以及规划与已实现结果的区别。
   只有年月的履历时间保留在条件中，不补造日期。图片内文字、客户 logo 和连线关系不会因此自动识别；纯图片空文本页跳过模型调用。
5. 提取或同步后自动运行不收费的本地结构检查，标记归属倒置、可能重复的单位及表面冲突。
   在 **检查与推导** 明确点击 **模型语义检查**，调用配置模型同时核对 RAGFlow 文本、
   原文件原生结构和相关的已审批事实。也可让持检查 MCP Token 的智能体完成核验。
   页面展示支持、待核对、与已审批前提冲突、证据不足及修改建议，均不等于审批。
   当前检查跳过已完成目标；候选或已审批上下文改变后会要求重查。
6. 在 **事实与审核** 的主体、属性、事实值三列中逐条查看证据、修正主体／属性／值／单位／条件／日期，确认或拒绝。
   也可选择多个候选，批量确认／拒绝，或导出 XLSX 审核后导入。
   XLSX 的 **核验与推导** 工作表按 fact_id 展示只读的检查意见、未审批建议、推导过程及前提状态；
   推导候选的 quote 是前提原文，不能视为文档直接披露结论。导入仅处理 facts 工作表。
   XLSX 对 PPT 软换行等 XML 不允许的控制字符做可逆转义，导入按工作簿编码标记还原；原始证据与防篡改校验保持不变。旧版未编码工作簿仍按原格式读取。
   来源证据中的分块还支持手动添加候选事实。
7. **确认** 和 **发布** 是独立操作。发布前检查同主体、属性、条件与时间范围的冲突；
   有冲突时先核对，明确淘汰错误或过时事实，不自动覆盖。
8. 已发布事实只有在来源当前、仍处于有效期内时才可查询。
   **允许外部引用** 必须明确勾选；MCP 的对外查询默认只返回允许外部引用的事实。

新版本来源会保留旧证据和审核记录，但旧版本事实停止提供。
修改 Prompt 会改变该库的提取版本，下次手动启动提取时按新版本处理。
提取上下文算法也计入版本，因此升级算法后下一次手动提取会重新处理；已完成的同版本分块仍可跳过。PPTX 布局算法有单独版本标识，升级它不会触发已完成 Word 分块的重新提取。
更换提取版本不会自动拒绝或覆盖旧候选；批量重新提取时须先备份，检查新旧结果后显式处理旧候选。
旧候选被拒绝或重新审核后，先前导出的 XLSX 会变为过期审核表，应重新导出当前待审核表。
相同内容仅在同一来源、同一提取版本且包括条件、有效期在内的字段完全一致时去重，保留原引用；不同项目或日期不会合并。
没有自动重复调用模型、自动确认候选或自动发布。

## MCP

端点：`https://facts.example.com/mcp`，Streamable HTTP。
在当前事实库生成 Token，配置到智能体：

```json
{
  "mcpServers": {
    "fact_manager": {
      "url": "https://facts.example.com/mcp",
      "headers": { "Authorization": "Bearer <该库生成的MCP Token>" }
    }
  }
}
```

Hermes 使用自己的 `mcp_servers` 配置键：

```yaml
mcp_servers:
  facts:
    url: https://facts.example.com/mcp
    headers:
      Authorization: Bearer <该库生成的MCP Token>
```

页面提供连接示例。把完整 Token 放入智能体的运行时凭据配置，避免提交到 Git。
MCP Token 自动决定所属事实库，工具不能请求另一个库。

- `get_library`：当前 Token 所属库的名称、说明与统计。
- `get_verified_facts(entity, attribute, for_external)`：已发布、当前且有效的事实；
  `for_external=true` 为默认值，内部使用可明确传 `false`。返回事实字段和直接／推导来源，
  未审批的检查意见及字段建议仅通过审核工具获取，不混入已发布结果。
- `search_evidence(query, limit)`：当前库来源的证据；RAGFlow 来源使用语义检索，
  本地文本使用原文子串匹配。证据不等于审核事实。
- `read_source(source_id, chunk_id)`：当前库有效来源的原文分块与文件哈希。

- `inspect_source(source_id, chunk_id)`：校验原文件 SHA256 和解析快照 SHA256，返回原生结构、
  RAGFlow 文本、页码、文件版本与未识别内容提示。提供带 Bearer 鉴权的原件下载地址，
  智能体可自行回看图片、图表与页面；不将原生文本解析视为图片理解。

选择 **检查** 权限的 Token 额外允许：

- `get_review_packet(fact_ids, offset, limit)`：候选字段、版本、引用、原文件结构和已审批上下文。
  最多40个目标、100条相关前提；返回省略条数，不能把有界上下文当成完整知识库。
- `submit_fact_check(...)`：提交检查意见和字段修改建议，必须提交目标 `expected_revision`；
  引用前提时还需 `premise_ids` 与 `premise_revisions`。建议不会覆盖候选或证据，
  用户明确点击“将建议填入表单”后仍须确认。
  使用核验包里的 `approved_context_revision` 可阻止检查过程中上下文变化导致的过期提交。
- `propose_derived_fact(...)`：以已审批且当前有效的事实为前提生成待审核推导；
  需传前提 ID、版本、推理过程、规则及结论字段。未审批事实不能作为确立前提。

所有 MCP 工具都不能审批、发布或管理 Token。撤销立即生效，已有 Cookie
不能代替 MCP Token。多个库的 Token 应作为不同 MCP server 配置到客户端。

## 原件、关联检查与推导

事实以 RAGFlow 解析与检索为主要文本入口，同时保存不可变原文件。核对时并用两种证据：
Word 原生段落和表格、PPTX 当前页文本框坐标及分组、PDF 原生页文本，以及本地 UTF-8 文本。
原件和分块都有 SHA256；原件丢失或被改动会阻止新审批、发布及已发布事实的提供。
PDF 图片、扫描件、PPT Logo 或连线不会自动理解，纯图片空文本页也会显式提示。
原文件结构读取范围有上限，完整内容以下载的原件核对为准。

已审批事实仍可能过时或有误。差异只有在主体、属性、时间、条件和计量口径一致时才可能构成矛盾；
不同项目、客户、测试、基线、目标与已实现结果不能简单互相否定。模型的“supported”
只表示已读取证据支持候选，绝非绝对真实性保证。冲突结论必须引用有效的已审批前提；
场景或前提可信度不明确时使用“需核对”。

**创建推导候选** 支持两种方式：

- `reasoned`：人工或智能体提出推理建议，记录结论、前提版本与推理过程，须核验业务含义。
- `ratio_complement`：对单条无修饰、无量纲且属性以“比例”结尾的前提，精确计算 `1 - 比例`。
  例如数量比例 `2/3` 的数学补比例为 `1/3`；补比例本身不自动表示减少率、成本节省或性能提升。
  这类业务解释仍需有明确基线、定义与场景支持。

推导始终先进入待审核、默认不允许外部引用。有效期限制在前提有效期交集内；
允许外部引用还要求全部上游前提允许外部引用。推导引用栏显示的是前提原文，
不能冒充文档直接披露了结论。页面另展示推导过程、前提及其有效状态。

前提被淘汰、内容改变、来源更新、缺失、过期或取消绑定，会即时停止提供依赖它的推导，
包括多层推导；保留旧审批与发布历史，需创建新推导并重新审批。不能独立改写推导结论，
否则推理和结论将不再一致。检查意见也记录引用前提与目标版本，过期后不能直接套用建议。

如果以后希望让我检查一批导入材料：先提取候选，再为该库配置一个检查权限 MCP Token。
我可读取核验包、下载原件、关联已审批事实，提交带依据的检查与推导候选；最后由你审批发布。
当前网页的模型检查使用配置的 DeepSeek，不能将其冒称为 Codex 已回看原件。

## 后续智能体接入

读取审核事实时，将上述 Hermes MCP 配置中的 `facts` 连接到事实系统，为相应库生成只读 Token。
需要辅助检查新材料时另生成检查 Token；管理员网页登录 Token 继续由服务运行时凭据管理。
生成材料前先读取 `get_library` 和 `get_verified_facts`，按主体、属性、条件和有效期判断适用范围；
缺少已发布事实时再检索证据并标为待核验，不把检索结果或推导候选当作已确认事实。
候选必须经网页确认、发布后才会出现在已发布接口中。
原始资料的通用语义检索还可独立连接 RAGFlow 原生 MCP；它使用 RAGFlow API Key。

## CLI

以下 `example` 请替换为 `libraries` 命令列出的实际库 ID。

```bash
fact-manager --config ./config.json libraries
fact-manager --config ./config.json --library example sync
fact-manager --config ./config.json --library example extract
fact-manager --config ./config.json --library example check-local
fact-manager --config ./config.json --library example check
fact-manager --config ./config.json --library example review-packet --offset 0 --limit 20
fact-manager --config ./config.json --library example review-export ./pending.xlsx
fact-manager --config ./config.json --library example review-import ./pending.xlsx --reviewer '你的姓名'
fact-manager --config ./config.json --library example publish --reviewer '你的姓名'
```

也可手动执行 `fact-manager sync` 同步所有事实库，跳过正在运行同步／提取／检查的库；
手动指定库的同步及模型任务遇到占用会返回错误，避免同库并发调用模型或更换证据。
提取、审核和发布必须显式指定库。
环境文件采用 `KEY=value`，不执行 Shell 展开。CLI 不需要管理员网页登录 Token。
